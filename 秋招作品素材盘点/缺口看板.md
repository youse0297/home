# 秋招作品素材缺口看板

优先级按“是否阻止可信投递”排序。P0 未完成前，不建议大规模投递；P1 决定作品集说服力；P2 用于后续版本优化。

| 编号 | 缺口 | 当前事实 | 下一步 | 验收标准 |
| --- | --- | --- | --- | --- |
| P0-01 | 本地 HLSL 提交未推送 | `HEAD c5758c5` 比 `origin/main 6d5b395` 领先 1 个提交 | 确认敏感信息后推送 | GitHub 可打开 HLSL commit、文档和发布包 |

## P1 作品集质量

| 编号 | 缺口 | 当前事实 | 下一步 | 验收标准 |

| P1-02 | CPU 过程图不足 | 只有坐标系图和最终三材质图 | 输出三角形、深度、UV、法线、GGX 分阶段图 | 每张图有输入、输出和一句结论 |
| P1-03 | HLSL 架构图缺失 | 模块关系只存在文档和 manifest 中 | 绘制依赖图与材质评估流程 | 图中包含 18 模块分组、聚合入口和两类消费端 |
| P1-04 | HLSL 视觉效果缺失 | 六模块图片是离线参考 | 在 Unity 中生成真实六模块场景 | 每个模块有固定机位的启用前后对照 |
| P1-05 | RenderDoc 捕获缺失 | 无 `.rdc` | 安装 RenderDoc，按 marker 捕获稳定帧 | 保存可打开 `.rdc` 和关键事件截图 |

| P1-07 | 赛博风格化主项目未见交付 | 阶段 2 目标尚无仓库证据 | 建立最小工程与 50% 定义 | 有效果目标、里程碑、运行视频和版本记录 |
| P1-08 | 个人贡献未确认 | 仓库无法证明协作方式 | 本人逐项确认设计、实现、测试和文档职责 | 每个项目有真实职责、难点、取舍和结果 |
| P1-09 | 仓库导航过长 | 根 README 信息完整但招聘阅读成本高 | 增加 30 秒入口和项目卡片 | 首屏能看到角色、强项、两个 Demo 和证据链接 |

## P2 后续优化

| 编号 | 缺口 | 下一步 | 验收标准 |
| --- | --- | --- | --- |
| P2-01 | 无英文版本 | 为项目标题、图注和 README 写英文摘要 | 中英文数字、链接和版本一致 |
| P2-02 | 无移动端作品集检查 | 在手机和窄屏检查图片、表格、视频 | 无横向溢出，视频可播放，链接可点击 |
| P2-03 | 无三分钟与十分钟讲稿 | 按目标、架构、难点、取舍、结果组织 | 两版录音均能在规定时间完成 |
| P2-04 | 无盲审记录 | 邀请同学或从业者做 5 分钟招聘视角审阅 | 保存前三个问题、修改和复审结果 |

## 本周最小闭环

1. 推送并核验当前 HLSL 提交。
2. 提供一份目标岗位 JD 和个人简历基础信息。
3. 录制 CPU 软渲染器 60 秒视频。
4. 解决 Unity 许可证或改用可运行环境补拍真实材质图。
5. 选择仓库许可证并创建 v1.0 Release。
